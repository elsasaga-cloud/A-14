## 🔴 硬伤 / 必须修复（影响使用或品牌形象）

### 1. 图片资源缺失风险

页面引用了3张产品图片，但未提供占位或后备方案。如果这些图片在服务器上不存在，会显示破碎图标，严重影响专业形象。

```html
<!-- 这三个 img 需要确保图片真实存在 -->
<img src="sti-488xggpm2b-2bt-front.jpg" ...>
<img src="stc-424xggpm-280w-front.jpg" ...>
<img src="sth-2c12xf12xe-hsi-front.jpg" ...>
```

**建议：**

- 确保图片上传到正确路径
- 或使用 `onerror` 回退到占位图
- 或暂时用CSS `background-color` 配合产品型号文字做视觉占位

---

### 2. 联系信息单一，缺少信任锚点

目前只有邮箱和WhatsApp，没有：

- 公司电话（哪怕是总机）
- 办公地址（只有"深圳"）
- 公司注册号或统一社会信用代码（针对中国客户）

对于B2B采购决策来说，联系方式过于单薄，可能降低信任度。

**建议：** 在Contact页面补充：

- 公司全称 + 注册地址
- 工作时间（时区说明）
- 如有，可放LinkedIn公司主页

---

### 3. "We Don't" 列表中存在逻辑矛盾

"UL certification" 和 "Country-specific mandatory certifications" 被列在"不做"清单中，但括号里又注明"available on request"。

这会让读者困惑：**到底是做还是不做？**

```html
<!-- 当前写法 -->
<li>UL certification (available on request for specific projects)</li>
<li>Country-specific mandatory certifications as standard (available on request, KC, etc.)</li>
```

**建议改为：**

- 在"We Do"中增加一条：*"Custom certifications (UL, KC, etc.) available on request"*
- 或在"We Don't"中改为：*"UL / KC certifications — not stocked as standard, but available on request for qualified projects"*

---

### 4. 页脚商标声明中的"MARVELL AND PRESTERA"全部大写

虽然不违法，但Marvell官方通常使用"Marvell"和"Prestera"（首字母大写，其余小写）。全部大写看起来像在喊叫，且与品牌官方写法不一致。

**建议改为：**

> Marvell® and Prestera® are trademarks of Marvell Technology, Inc. CENTEC® is a trademark of CENTEC Communications.

---

### 5. 页面加载时 `gotoPage('home')` 被调用了两次

页面底部脚本中：


紧接着又调用了：

```javascript

```

虽然不影响功能，但属于冗余代码，建议删除重复调用。

# Saga Telecom 全站HTML完整审核报告

分四大维度：**前端代码硬伤（语法/性能/兼容性/安全）**、**页面结构与交互逻辑缺陷**、**文案表述&SEO语义问题**、**业务体验&工程规范短板**，每条标注严重等级+修复方案。

## 一、前端代码硬伤（高危/中危/低危）

### （一）高危安全&合规问题

1. **WhatsApp外链无安全完整属性**
   ```html
   <a class="wa-float" href="https://wa.me/8615237149683" target="_blank" rel="noopener">
   ```
   缺失 `noreferrer`，新窗口打开会泄露页面来源Referrer，标准规范应为 `rel="noopener noreferrer"`。
2. **内联事件存在XSS风险**
   全页面大量 `onclick="gotoPage('home')"`、`onclick="toggleInsight(1)"`
   - 内联事件脱离JS作用域管控，若后续动态拼接参数极易触发XSS；
   - 不利于代码解耦、事件统一管理、埋点统计。
3. **缺少CSP、Meta安全头**
   HTML头部无 `Content-Security-Policy`、`X-Content-Type-Options`、`X-Frame-Options`，生产环境易被点击劫持、资源注入。
4. **图片无兜底加载容错**
   产品图直接写 `<img src="xxx.jpg" alt="xxx">`，无 `onerror` 兜底图，图片404时页面留白破损；无 `loading="lazy"` 大图阻塞首屏。

### （二）中危性能&渲染缺陷

1. **全局硬编码样式，无CSS变量分层、冗余严重**
   - 大量行内样式 `style="padding:64px 0 56px;"`、重复写同一段边框/间距代码；
   - 响应式断点仅 `880px/540px`，缺少平板、大屏适配；媒体查询内重复重置网格布局，CSS体积冗余。
2. **无图片尺寸预定义，布局偏移CLS严重**
   产品卡片仅设置 `aspect-ratio:1/1`，但未给img固定宽高，图片加载前后页面布局抖动，影响Google Core Web Vitals评分。
3. **JS逻辑全写页面底部，无延迟/按需加载**
   脚本直接写在footer末尾，无 `defer/async`；Insights文章切换、页面切换逻辑全部全局执行，首页不需要的文章JS仍阻塞解析。
4. **页面切换使用display****:none****，DOM未懒卸载**
   所有页面DOM一次性渲染在页面，页面越多DOM体积越大，首次加载DOM节点过多，低端设备卡顿；无虚拟滚动/懒加载内容。
5. **字体无fallback兜底、中文渲染差**
   全局使用 `Times New Roman、Courier New`，无中文字体兜底（`SimSun, Microsoft YaHei`），Linux/国产系统中文方块乱码。

### （三）低危语法&规范错误

1. **HTML语义化大量缺失**
   - 导航用 `<nav><ul><li><button>`，而非 `<a>`；页面内跳转应该用锚链接，改用button破坏语义、不利于爬虫；
   - 文章Insights无 `<article>`、`<time>` 语义标签，纯div堆砌；
   - 联系方式面板 `<dl>` 规范使用勉强合格，但无 `aria-label` 无障碍说明；
   - 缺少 `<main>` 主内容容器、`<section>` 未全部搭配标题层级。
2. **无障碍a11y缺陷**
   - 悬浮WhatsApp按钮仅简单 `aria-label`，tooltip无键盘聚焦逻辑；
   - 所有导航按钮、折叠文章仅鼠标点击，无键盘回车/空格触发兼容；
   - 色彩对比度：`var(--accent):#8a2e1f` 浅米色背景下文字对比度偏低，视力障碍用户难阅读；
   - 折叠面板无 `aria-expanded`、`aria-controls`，读屏软件无法识别展开/收起状态。
3. **图标SVG无优化**
   WhatsApp SVG内联但无精简、无 `fill-rule` 优化，重复代码；未使用symbol雪碧图，重复占用HTML体积。
4. **Meta细节缺失**
   - 无viewport `user-scalable=yes` 限制放大，部分移动端缩放异常；
   - 缺少 `theme-color` 浏览器状态栏适配；
   - OG图片仅一张，无分页面独立OG封面，分享所有页面都显示同一张图。
5. **重复资源加载**
   多个favicon尺寸重复定义，无 `media` 区分加载时机；GA4、站长验证代码直接硬编码，无法环境隔离（测试/生产共用）。
