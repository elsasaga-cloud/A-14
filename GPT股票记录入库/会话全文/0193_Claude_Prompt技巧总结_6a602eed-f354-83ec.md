你总结的方向基本对，但可以再细化一下。Claude（尤其是 Claude 3.5/3.7/4 系列）和 GPT 的 prompting 风格有一些差异。

简单说：

> **Claude 更像一个“高级分析师/顾问”，擅长长文本、复杂推理、结构化任务；但它非常吃上下文质量。**
>
> 你给它的输入越像一份“任务说明书”，输出越稳定。

下面讲一些比较实用的技巧。

---

## 1. 不要直接扔 PDF，让它“自己看”

这个网上说法有一定道理，但不是绝对。

Claude 能处理 PDF，但问题在于：

### PDF ≠ 文本

很多 PDF 实际结构：

```
图片
扫描页
复杂表格
双栏排版
图表
脚注
隐藏格式
```

模型看到的可能不是你肉眼看到的东西。

比如：

你上传一个：

《Marvell Prestera Switch Architecture.pdf》

你希望：

> 分析芯片架构、提炼卖点、找客户价值

但是 PDF 里面：

```
Figure 12
Table 4
Block Diagram
```

可能被解析成：

```
Figure...
[image]
Table...
```

大量信息丢失。

---

更好的方式：

### 方法1：PDF转文本

比如：

PDF

↓

Markdown/Text

↓

Claude


效果通常明显提升。

尤其：

- 技术白皮书
- 财报
- 论文
- 标准协议
- 产品手册


---

### 方法2：分阶段

不要：

> 帮我分析这个100页PDF


改：

第一轮：

> 阅读这个文档，只做信息提取，不分析。


第二轮：

> 基于刚才提取的信息，分析商业价值。


第三轮：

> 根据分析结果，生成销售话术。


原因：

一次让模型：

阅读 + 理解 + 分析 + 创作

容易丢东西。


---

# 2. Prompt最好像“需求文档”

很多人：

❌

> 帮我看看这个产品怎么样


模型不知道：

- 面向谁？
- 什么目标？
- 什么深度？


---

好的：

```
你现在扮演通信行业产品经理。

背景：
我们是一家做网络设备出口的公司。

目标：
分析这个产品是否适合进入欧美市场。

请从以下几个维度分析：

1. 技术优势
2. 竞争壁垒
3. 目标客户
4. 销售卖点
5. 风险

要求：
不要泛泛而谈，需要结合具体规格。
```

这个效果完全不同。

---

# 3. 明确角色（Role Prompt）

Claude特别吃这一套。


比如：

## 技术分析

```
你是一名有15年经验的网络设备架构师。

熟悉：
- Marvell Prestera
- Broadcom
- Cisco
- Juniper

请从专业工程角度分析。
```


---

## 投资分析

```
你是一名长期价值投资者。

你的分析框架：

1. 商业模式
2. 护城河
3. ROIC
4. 估值
5. 风险


不要预测短期股价。
```

---

角色不是为了装逼。

作用是：

给模型一个知识边界。

---

# 4. 明确“不允许做什么”

这个非常重要。

很多人只告诉AI：

我要什么。

但高手会告诉：

不要什么。

例如：

```
不要：
- 编造数据
- 使用没有依据的信息
- 泛泛解释

如果信息不足，请明确说明。
```

效果提升明显。

---

# 5. 给评价标准

这是很多普通用户不会用的。

比如：

不要：

> 写一个销售邮件


改：

```
评价标准：

优秀邮件应该：

- 让客户3秒知道价值
- 不超过150字
- 避免技术堆砌
- 突出差异化

请按照这个标准生成。
```


模型会自动优化。


---

# 6. 分点不是重点，重点是“任务拆解”

很多人说：

> Prompt要分点


其实不是。

真正有效的是：

把复杂任务拆成几个认知步骤。


比如：

你让Claude分析一个交换机市场：

不要：

```
分析这个交换机市场
```

应该：

阶段1：

```
提取产品信息
```

阶段2：

```
分析竞争环境
```

阶段3：

```
寻找市场机会
```

阶段4：

```
生成销售策略
```


这叫 Chain of Thought 工作流。

---

# 7. Claude特别适合“先讨论，再输出”

这是它比很多模型强的地方。

比如：

不要：

```
帮我制定投资策略
```

而：

```
先不要给结论。

请作为投资顾问，与我讨论：
1. 我的目标
2. 我的风险承受能力
3. 我的约束

确认后再输出方案。
```


Claude很适合这种。

---

# 8. 长上下文使用技巧

Claude最大的优势就是长上下文。

但是很多人浪费。

错误：

```
上传10个文件
然后：
帮我总结
```

模型会迷失。


更好：

建立：

## Context

```
背景资料：

公司：
xxxx

产品：
xxxx

竞争：
xxxx

目标：
xxxx
```


然后：

```
以下所有问题，都基于这个背景。
```


类似给员工培训。


---

# 9. 对技术/商业分析特别有效的 Prompt 模板

比如你的通信行业：

可以这样：

```
角色：
你是一名通信行业战略顾问。

背景：
我公司提供：
- PoE Switch
- L2+/L3 Switch
- Optical Transport

客户：
海外SI、ISP、政府项目。


任务：
分析这个产品进入市场的机会。

请输出：

1. 产品定位
2. Ideal Customer Profile
3. 竞争对手
4. 差异化卖点
5. 销售话术
6. 下一步行动

要求：
结合行业实际，不要生成普通营销语言。
```


这个比：

"帮我推广这个产品"

强几十倍。

最后总结一句：

高级Prompt不是“魔法咒语”。

核心就是：

> **给AI足够的上下文 + 明确目标 + 限制边界 + 定义输出标准。**

普通用户：

“分析这个”

高手：

“你是谁 → 背景是什么 → 要解决什么 → 用什么标准判断 → 输出什么格式 → 不允许什么”

这就是差距。你现在做产品、投资、商业分析，其实已经接近第二种用法了。你缺的不是Prompt技巧，而是把自己的商业框架“结构化喂给模型”。
