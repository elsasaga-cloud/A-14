---

# 1. Larch Networks 和 Marvell 什么关系？

不是直属关系。  
不是“Marvell 子公司”。

更准确说：

```text
Marvell = 芯片平台
Larch = 基于 Marvell 做 NOS/BSP/平台适配的软件公司
```

类似：

| 角色 | 类比 |
|---|---|
| Marvell | Intel / AMD |
| Larch | BIOS + Linux + 驱动 + NOS集成商 |

他们核心价值其实是：

- 帮硬件厂把 Marvell switch ASIC 真正跑起来
- 做：
  - BSP
  - SDK integration
  - SONiC
  - Linux networking
  - 平台适配
  - 长期维护

因为很多厂：
- 会做硬件
- 但不会做 NOS

尤其 SONiC。

SONiC 真不是：
> “装个 Linux”

那么简单。

涉及：
- SAI
- ASIC abstraction
- switchdev
- orchestration
- Redis DB
- containerized network stack
- platform API
- thermal/fan/PSU management
- transceiver management

小厂基本搞不定。

所以就需要：
- Larch
- IP Infusion
- Pica8
- Arrcus
- DriveNets

这种公司。

---

# 2. 它牛逼吗？

分层看。

## 对比 Cisco/H3C/Juniper

当然不牛。

体量差太远。

---

## 但在“小众开放网络生态”里

它是有点东西的。

因为：

### 它能活下来

这个行业很难活。

做 NOS 的公司：
- 技术极重
- 客户极少
- 项目周期长
- 非标准化
- 要长期维护

能持续运营很多年的，通常都有真实能力。

---

### 它能和 Marvell 深度合作

这点重要。

Marvell 不是随便开放底层生态的。

能拿到：
- SDK
- 支持
- reference platform
- 技术协作

说明：
- 他们至少是 ecosystem partner

---

### 它客户不算差

你截图里：
- ADVA
- Cobham
- Amphenol
- CRSI

这些都不是小白公司。

尤其：
- ADVA（光网络）
- Cobham（航空/国防）
- Amphenol（连接器巨头）

说明他们确实接过正经项目。

---

了。
